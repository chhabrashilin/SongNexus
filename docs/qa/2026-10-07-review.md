# QA review: v2 through M5 (2026-10-07)

Scope: server (catalog, core, service, identity), web, deployment config. Each finding was verified against
the code, the installed library source, or platform documentation, not assumed. Severity: **P0** breaks a core
journey or loses data in production; **P1** security, privacy or reliability risk; **P2** quality defect;
**P3** polish.

| ID | Sev | Area | Finding | Evidence | Fix |
|---|---|---|---|---|---|
| Q1 | P0 | Identity | Session cookie never reaches the API in production: Firebase Hosting strips all cookies except `__session` on Cloud Run rewrites. Sign-in would silently fail. | Firebase Hosting docs (cache behavior); our cookie is `__Host-songnexus_session` | Cookie renamed `__session` (Secure, HttpOnly, SameSite=Lax, Path=/); ADR 0002 amended |
| Q2 | P0 | Service | Writes commit **after** the response is sent: request-scoped `yield` dependencies exit after `await response(...)` (FastAPI 0.142 `routing.py`). | Q3 | P0 | Catalog | Quality gate runs after the data is committed and marked `succeeded`, so serving instances load a catalog that failed the gate. | `ingest_snapshot` then separate `quality` CLI | Gate runs inside the ingest transaction; a failing gate rolls back and marks the run failed |

## Verified fine (no change)
- CSRF: writes require an allowed `Origin` plus the session-bound token; sign-in requires `Origin`.
- Authorization: every `users/{user}` method goes through one check; the matrix test covers 11 calls.
- React inline styles are applied through CSSOM, which `style-src 'self'` permits.
- `GET :export` is not CSRF-relevant (responses go to the victim, not the attacker).
