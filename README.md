# SongNexus

**A provenance-aware music knowledge graph with grounded, explainable discovery.**
UW–Madison CS 620 capstone, built on the Google project brief *Chladnigraph: Musical Connections*.

> The graph computes. The agent orchestrates. The model explains. The evidence decides.

SongNexus turns public music metadata into a graph of who performed, produced, played on,
sampled and formed bands with whom. It lets you explore it visually, find how any two artists
are connected, and ask questions in plain language. Every connection can be traced back
to the source record it came from; nothing shown as a fact is generated by a language model.

## What works today (vertical slice)

| Capability | Status | Where |
|---|---|---|
| Reproducible MusicBrainz ingestion (snapshot → validate → normalize → resolve → persist) | ✅ | `backend/songnexus/pipelines/` |
| Entity resolution: seed-name resolution that refuses to guess, recording deduplication | ✅ | `resolution/matcher.py`, `pipelines/canonicalize.py` |
| Provenance on every fact (source, raw record, run, pipeline version, confidence) | ✅ | `db/models.py`, `GET /provenance/*` |
| Typo-tolerant search over artists, aliases, tracks, albums | ✅ | `search/index.py` |
| Interactive force-directed graph with progressive expansion and filters | ✅ | `frontend/src/graph/GraphCanvas.tsx` |
| Degrees of separation: bidirectional BFS, strongest path (Dijkstra), alternatives (Yen) | ✅ | `graph/algorithms.py` |
| Centrality: weighted PageRank, Brandes betweenness, degree | ✅ | `graph/algorithms.py` |
| Grounded agent: allow-listed tools, evidence ledger, grounding verifier, Claude or deterministic planner | ✅ | `backend/songnexus/agent/` |
| Data-quality checks, search/agent evaluation harnesses, path benchmarks | ✅ | `pipelines/quality.py`, `evaluation/` |
| **SongNexus Daily**: a daily connection puzzle with hints, a spoiler-free share card and warmer/colder feedback | ✅ prototype | `services/game_service.py`, `frontend/src/components/PlayPanel.tsx` · [vision](docs/vision.md) |
| Community detection, similarity, semantic/hybrid search, second data source, Connections puzzles | 🗺️ Planned | [docs/roadmap.md](docs/roadmap.md) |

(recorded 2026-09-30 on a Windows 11 laptop, Python 3.14, SQLite). Re-run with `make eval bench`.
Treat them as a regression baseline, not a general claim: the dataset is a 28-artist sample,
and the evaluation sets are small and were written by the team.

| Metric | Value |
|---|---|
| Canonical artists / fully loaded discographies | 2,259 / 28 |
| Tracks · albums · track credits · artist relationships | 1,391 · 102 · 13,699 · 216 |
| Artist-graph connections (default categories) · largest component | 4,300 · 1,798 artists |
| Data-quality checks passing | 18 / 18 |

| Search latency p50 / p95 (in-process) | 17 ms / 33 ms |
| Bidirectional vs unidirectional BFS: mean nodes expanded (300 pairs) | **16** vs 268 |
| Path query latency p50 (bidirectional BFS / Dijkstra) | 0.07 ms / 4.0 ms |
| Agent, deterministic mode (20 cases): task success · grounded · unsupported-claim rate | 0.90 · 1.00 · 0.00 |

## Quick start

**Option A: Docker** (PostgreSQL + API + UI):

```bash
cp .env.example .env          # optional: add ANTHROPIC_API_KEY to enable LLM mode
docker compose up --build     # UI http://localhost:8080 · API docs http://localhost:8000/docs
```

The backend loads the committed sample snapshot on first start.

**Option B: local development** (no Docker needed; uses SQLite by default):

macOS / Linux:

```bash
python -m venv .venv
.venv/bin/pip install -e "backend[dev,llm]"
.venv/bin/songnexus ingest && .venv/bin/songnexus quality
cd backend && ../.venv/bin/uvicorn songnexus.api.app:create_app --factory --port 8000
# second terminal
cd frontend && npm ci && npm run dev              # http://localhost:5173
```

Windows (PowerShell 5.1 has no `&&`, and venv executables live in `.venv\Scripts`):

```powershell
python -m venv .venv
.venv\Scripts\pip install -e "backend[dev,llm]"
.venv\Scripts\songnexus ingest
.venv\Scripts\songnexus quality
cd backend
..\.venv\Scripts\uvicorn songnexus.api.app:create_app --factory --port 8000
# second terminal, from the repo root
cd frontend
npm ci
npm run dev                                        # http://localhost:5173
```

For Docker on Windows, start Docker Desktop and wait for "Engine running" before `docker compose up --build`.

Try it: search **Kendrick Lamar**; in *Connect*, go from **Miles Davis** to **Drake**; in *Ask*,
type *"How is Daft Punk connected to Kamasi Washington?"*.

**Checks:** `make lint typecheck test` (or the commands in [docs/testing.md](docs/testing.md)).

## How it fits together

```
MusicBrainz API ──fetch (rate-limited, cached)──▶ snapshot.jsonl.gz  (committed, reproducible)
                                                     │  ingest: validate → normalize → resolve
                                                     ▼
                              PostgreSQL: raw_records │ canonical entities │ facts + provenance
                                                     │  project at startup / after ingestion
                                                     ▼
                         Read model (immutable): artist graph with evidence + search index + caches
                                                     │
            FastAPI /api/v1: search · artists · graph/path · centrality · provenance · agent/query
                                                     │
      React + D3: Explore (force graph) · Connect (paths) · Ask (grounded agent) · Evidence & sources
```

Details: [docs/architecture.md](docs/architecture.md).

## Data and licensing

Graph data comes from [MusicBrainz](https://musicbrainz.org). Its core data is released under
CC0 and is used here with attribution. The committed snapshot covers the four most-rated studio albums of 28
seed artists plus everyone credited on them. Absence of a connection in SongNexus means *absent from
this dataset*, never *absent in reality*, and the UI and agent say so.
